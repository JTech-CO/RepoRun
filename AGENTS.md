# RepoRun maintenance

Preserve the product boundary: evidence-first, read-only inspection of one directory on a pinned default-branch commit. Never execute/import repository code, generate unsupported requirements, or turn a heuristic into a compatibility claim.

Keep GitHub access inside the worker. Native fetch must remain bound to the real global receiver. Keep endpoint allowlisting, sender validation, auth epochs, byte/time limits and session-only credentials. No publisher backend or telemetry.

All user text uses DOM text nodes. Any rule must state declared/inferred/unknown and source evidence. Add adversarial and uncertainty fixtures when changing the analyzer. EN/KR strings and all branding surfaces must stay aligned.

Run `npm run package`. Browser checks are optional Python scripts under tests; report exactly which were run and never equate offline fixtures with installed MV3/live GitHub verification. Source releases must include reproducible tests and honest QA notes.

Launcher placement is About sidebar first, then one 44px bottom-right fallback. Never put RepoRun into the repository header actions. Keep placement, focus and duplicate-host regression checks under tests/placement_qa.py.
