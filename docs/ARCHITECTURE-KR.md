# RepoRun 1.0.1 아키텍처

[English](ARCHITECTURE.md) · [README](../README-KR.md)

## 핵심 경로

GitHub의 격리된 콘텐츠 스크립트는 URL·저장소 식별자를 읽어 버튼만 배치합니다. 방문 자체로 분석 API를 호출하지 않습니다. 사용자가 분석을 요청하면 서비스 워커가 메시지 namespace·확장 ID·발신 페이지·최상위 프레임·허용 작업을 확인합니다. 페이지에서는 임의 URL이나 토큰 관리 작업을 요청할 수 없습니다.

저장소 메타데이터에서 기본 브랜치를 구하고 HEAD를 한 번 조회하여 커밋·트리 SHA를 고정합니다. 이후 디렉터리는 비재귀 Git 트리, 파일은 blob SHA로 조회합니다. 따라서 파일마다 다른 최신 버전이 섞이지 않습니다. 지정한 디렉터리 하나의 허용 파일만 읽어 순수 분석기에 전달합니다. UI에는 토큰·파일 원문 모음이 아니라 정규화한 보고서만 돌려줍니다.

```text
GitHub 버튼 -> 검증된 메시지 -> 서비스 워커
  -> 메타데이터 -> 기본 브랜치 커밋·트리 SHA 고정
  -> 해당 디렉터리의 비재귀 트리 -> 일부 정규 파일 본문
  -> 결정적 분석기 -> 세션 보고서 -> 개요 / 명령 / 근거 / 내보내기
```

## 모듈 경계

`shared/core.js`는 입력·경로·오류·상한·링크를 검증하고, `analyzer.js`는 파일에서 근거를 추출합니다. `i18n.js`는 EN/KR, `ui.js`는 텍스트 노드 렌더링·복사·보고서·로고를 담당합니다. CSS 원본은 `styles.css`이며 빌드 시 `styles.js`를 생성합니다.

`background/github.js`만 외부 요청을 수행합니다. 네이티브 fetch는 `globalThis`에 bind하여 RepoDelta에서 발생했던 receiver 오류를 예방합니다. 읽기 GET·쿠키 제외·시간 및 스트림 바이트 제한을 적용합니다. HTTP 오류, 파싱 실패, 네트워크 오류, Illegal invocation 같은 프로그래밍 오류를 구분하며 임의 호환성 재시도는 하지 않습니다.

`store.js`는 언어만 로컬에, 토큰·한도·보고서는 세션에 보관합니다. TRUSTED_CONTEXTS 접근 제한과 직렬 쓰기를 사용합니다. 인증 세대가 바뀌면 기존 응답을 새 캐시에 적용하지 않습니다. `service.js`는 경로 선택·본문 시도 상한·동일 요청 합치기·캐시·발신자 검증을 담당합니다. 동시에 서로 다른 분석은 최대 3개입니다.

콘텐츠 UI는 Shadow DOM과 native dialog를 사용합니다. 설정은 토큰·언어·진단·캐시 관리, 팝업은 현재 저장소의 패널과 설정 진입만 담당합니다.

## 네트워크 및 권한

메타데이터, 기본 브랜치의 최근 커밋, Git 트리, 선택한 Git blob에 대한 GET과 사용자 진단용 `/rate_limit`만 사용합니다. 응답의 최종 API 출처도 검사합니다. 토큰은 URL에 넣지 않습니다. 원문 근거는 사용자가 GitHub 링크를 열어 확인합니다.

권한은 storage, github.com, api.github.com입니다. 방문 기록·쿠키·전체 사이트·네이티브 메시징 권한은 없습니다. GitHub에 노출하는 확장 자산은 `icons/logo.svg`뿐입니다. 원격 코드를 가져와 실행하지 않습니다.

## 확장 시 유지할 조건

새 분석 규칙은 파일을 실행하지 않는 근거 추출로 구현합니다. 없는 값을 생성하거나 프레임워크만 보고 배포 가능성을 확정하지 않습니다. 새 본문 조회는 허용 목록·크기·시도 횟수 안에 들어가야 합니다. Mock API 테스트뿐 아니라 실제 Worker의 receiver 회귀도 유지합니다.

공식 문서와 API 경로 목록은 [영문 아키텍처](ARCHITECTURE.md)에 있습니다.
